# Enigma Lab — 恩尼格玛与 Bombe 拆解检视台

两台机器的交互式三维教学模型：

- **恩尼格玛 I 型**：按维修手册的方式一步步拆开——放下前翻板、掀起转子盖、取出转子组、沿轴分开、取下一枚转子、把它拆成拇指轮／数字环／线芯／棘轮，再透视机体内部。任何零件都可以点选隔离，其余部分变成线稿式 X 光，图上用编号引线标注细节。也能真实加密：先看转子步进，再看电流去程（琥珀）和回程（青绿）穿过透视的线芯。
- **Turing–Welchman Bombe**：用一份截获的空军天气报告，从猜词、冲突、菜单、闭环、把插线板“消掉”、电路矛盾、对角板，一直走到真实运行 17,576 个位置、核对停机、恢复插线与环设置并读出全文。滚筒、测试寄存器、背面接线门和继电器架同样可以拆解检视。

两台机器都按写实做旧的方式渲染，界面是暖黄的档案风格（另有深色版），中文 / English，偏好保存在当前浏览器。在任何页面点击模型上的部件都能单独检视它。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址（开发服务只监听 `127.0.0.1`）。地址后加 `#bombe` 直接进入 Bombe。生产构建：

```sh
npm test
npm run build
npm run preview
```

`dist/` 是纯静态网站，可直接部署到 GitHub Pages（工作流见 `.github/workflows/deploy.yml`，步骤见 [DEPLOYMENT.md](./DEPLOYMENT.md)）。字体随项目打包，运行时不依赖外部资源。

## 恩尼格玛 I 型

| 面板 | 内容 |
| --- | --- |
| 拆解检视 | 8 步拆解轨道（可拖动、逐步、自动演示）；图号标题栏、编号标注、参数、下一级零件、完整零件清单。点击模型逐级深入（整机 → 转子组 → 中转子 → 线芯），Esc 或面包屑返回上一级。 |
| 加密操作 | 修改转子、环设置、起始位置、反射器和插线；屏幕键盘或电脑键盘输入；三维电路展开视图、灯板、26 触点阶梯图、逐级映射表、电文批量加密与复位。 |
| 数学原理 | 逐个部件回答“它解决了什么问题，又留下了什么破绽”：单表替换为何不够 → 转子 Rₖ = ρ⁻ᵏ·W·ρᵏ（可拖动的替换表）→ 步进与周期 → 反射器 Eᵢ = Q⁻¹UQ → 插线板 Cᵢ = S·Eᵢ·S，最后列出设计决定与破译手段的对应表。 |

转子的线芯与数字环在模型里是两个相对转动的部件：数字环随窗口读数 p 转动，线芯再相对它转过环设置 r，所以触点、导线和读数窗始终与加密内核一致。透视状态下看到的 26 根铜线就是该型号转子的真实接线。

## Turing–Welchman Bombe

破译原理按 9 步展开。每一步先提问，再试最直接的办法，看它为什么碰壁，由此推出下一步的必要性；数字都来自真实计算：

1. **截获电文**：穷举 1.07 × 10²³ 把钥匙不可能；拆开这个积，发现目标是“不知道插线板也能检验转子状态”，而这需要明文。
2. **猜词与拖动**：德军报告格式刻板，所以能猜到明文；位置未知，靠“字母不加密成自己”排除约一半错误位置。
3. **画出菜单**：S 出现两次无法直接用，利用 S² = 1 改写成 S(c) = Eᵢ(S(p))。一个猜测能推出下一个结论，字母怎样相连决定推理能走多远，这张路线图就是菜单。可以亲手选位置和假设，一步步推到撞车。
4. **消掉插线板**：撞车只发生在绕回已知字母时，闭环给出 x = Π(x)，方程里只剩一个未知字母。
5. **把推理接成电路**：手工要查 4.4 × 10⁸ 次表，于是让电流去做推理，语句与导线逐项对应。
6. **矛盾即排除**：错误假设一错到底，一次通电同时测完 26 个假设。26 × 26 导线网格逐层显示。
7. **对角板**：不开时本菜单停机 787 次，其中 656 次恰有 1 根线没亮；S(a) = b ⟺ S(b) = a 这条信息还没用上，接上后降到 3 次。
8. **运行与停机**：滚筒真实转过 17,576 个位置，可调速，可一次跑完全部 60 种转子排列。
9. **核对与解密**：沿菜单推全部插线，假停机露出矛盾；再试出环设置，读出全文，并可与真实密钥对照。

“换一份”会随机生成新的密钥（保证猜词范围内中转子不进位、菜单至少有两个闭环），整套流程照样成立。

## 正确性

自动化测试 **194 项**全部通过：

- 121 项独立参考：固定版本 Py-Enigma 1.0.2 生成的 120 种配置（60 种转子排列 × B/C 反射器、0–10 对插线、跨进位长报文）共 105,240 个字母逐字一致。
- 49 项内核测试与 4 项插线回归测试（保留自上一版）。
- 20 项 Bombe 测试：扰频器与带追踪的加密引擎逐字一致、为无不动点对合；运行顺序；猜词冲突；最短闭环；真实位置必停且测试寄存器死线就是 S(E)；注入真插线时只亮 1 根；对角板把停机从 787 降到 3；广度优先的电流传播与并查集结果一致、对角板网格对称；核对后只剩一个自洽假设并还原全部插线；假停机全部被排除；恢复环设置、起始位置与全文；随机电文满足前提；手工沿菜单推理时，真插线不撞车且还原全部插线，其余 25 个假设全部撞车。

## 精度边界

- 加密、步进、Bombe 推理与停机是精确计算；三维几何是依据照片与文字资料的教学建模，**不是测绘或制造尺寸复刻**。导线弯曲、机体内部机构的位置、Bombe 背门插孔排布与电缆走向是示意，电气端点与对应关系准确。
- Bombe 的“位置”指猜词第一个字母加密时三枚转子的线芯偏转（窗口 − 环设置），这是机器真正能判定的量；第 i 条边的扰频器在右转子上加偏移 i。这与历史上把菜单写成相对偏移的做法等价，但不是 Bletchley Park 记录停机的原始格式。
- 与真实菜单一样，模型假设猜词范围内中转子不进位；生成随机电文时会保证这一点。
- 对角板之外，Bombe 的继电器时序、“1.5 圈进位”等机电细节未仿真；停机判据按“测试寄存器有任一根线没电即停”。

## 代码结构

```
src/
  core/        纯 TypeScript：enigma（加密与轨迹）、bombe（扰频器、菜单、运行、传播、核对、密钥恢复）、scenario（截获电文）
  engine/      Stage（React Three Fiber + drei：共享画布、相机、拾取、环境光）、Exhibit（零件树、拆解步骤、隔离 / X 光、标注锚点）、做旧材质与程序贴图
  machines/
    enigma/    模型、零件目录与拆解步骤、电流叠加层、操作 / 原理面板
    bombe/     模型、零件目录与步骤、破译讲解（story）、各步图纸（猜词、菜单、导线网格、核对）
  ui/          讲解组件（KaTeX 公式）、标注引线层、拆解轨道、零件档案
  styles/      设计变量（明 / 暗）与布局
```

主要依赖：React Three Fiber 与 drei 负责渲染循环、CameraControls、拾取、环境光和接触阴影；@react-three/postprocessing 提供环境光遮蔽（N8AO）；HDRI 来自 @pmndrs/assets；KaTeX 排版公式；d3-force 布局菜单图；motion 负责帧调度与补间；lucide-react 提供图标；字体来自 Fontsource。没有现成库能替代的部分保留自写：零件树的拆解位姿（Exhibit）、程序化模型和密码内核。

参考资料与核查记录见 [RESEARCH.md](./RESEARCH.md)。
